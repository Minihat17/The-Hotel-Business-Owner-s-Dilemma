# Hotel Business Analytics: Revenue & Optimization Project

## 🏨 Scenario & Background
โครงการนี้มุ่งเน้นไปที่การแก้ปัญหาของเจ้าของธุรกิจโรงแรมที่กำลังเผชิญกับสภาวะ **Revenue Stagnation** (รายได้หยุดนิ่ง) แม้จะมีจำนวนผู้เข้าพักในระดับที่น่าพอใจ แต่รายได้ต่อห้องพักที่ว่าง (**RevPAR**) กลับต่ำกว่าคู่แข่ง ซึ่งสะท้อนถึงการขาดประสิทธิภาพในการกำหนดราคา (Pricing) และการจัดการสินค้าคงคลัง (Inventory Management)

## 🎯 Research Objectives
1. **วิเคราะห์โครงสร้างข้อมูล:** ศึกษาตาราง `fact_bookings` ซึ่งเป็นปัจจัยหลักที่ส่งผลต่อรายได้
2. **หาสาเหตุของปัญหา:** วิเคราะห์ตัวแปรต่างๆ ที่ทำให้รายได้ไม่เติบโตตามเป้าหมาย
3. **พิสูจน์สมมติฐาน:** สร้างสมมติฐานและใช้ข้อมูลสนับสนุนเพื่อหาแนวทางการแก้ไข
4. **วัดผลด้วย KPIs:** คำนวณตัวชี้วัดสำคัญเพื่อคาดการณ์แนวโน้มธุรกิจ
5. **ประเมินการใช้ Model:** วิเคราะห์ความเป็นไปได้ในการนำ Model มาช่วยเพิ่มประสิทธิภาพในการตัดสินใจ

## 📊 Key Performance Indicators (KPIs)
ตัวชี้วัดหลักที่ใช้ในโครงการนี้:

| KPI | คำจำกัดความ | สูตรคำนวณ |
| :--- | :--- | :--- |
| **RevPAR** | รายได้ต่อห้องว่างทั้งหมด | รายได้ห้องพักทั้งหมด / จำนวนห้องว่างทั้งหมด |
| **ADR** | ราคาเฉลี่ยต่อห้องที่มีผู้เข้าพักจริง | รายได้ห้องพักทั้งหมด / จำนวนห้องที่ขายได้ |
| **OCC** | อัตราการเข้าพัก (%) | (จำนวนห้องที่ขายได้ / จำนวนห้องว่างทั้งหมด) * 100 |
| **LOS** | ระยะเวลาที่เข้าพักจริง (คืน) | วันเช็คเอาต์ - วันเช็คอิน |
| **BLT** | ระยะเวลาการจองล่วงหน้า (วัน) | วันเข้าพัก - วันที่จอง |

## ❓ Research Questions & Hypothesis
* พฤติกรรมการจองห้องพักของลูกค้าในปัจจุบันเป็นอย่างไร?
* ปัจจัยด้าน Seasonality, ประเภทห้องพัก และโปรโมชั่น ส่งผลต่อรายได้อย่างไร?
* การนำ Model เข้ามาปรับใช้จะช่วยแก้ปัญหารายได้หยุดนิ่งได้มีประสิทธิภาพเพียงใด?

## 🛠 Methodology & Data Cleaning
กระบวนการเตรียมข้อมูลเพื่อให้พร้อมสำหรับการวิเคราะห์:
* **Uniform Date Format:** ปรับปรุงข้อมูลวันที่ในตาราง `fact_bookings` (เดิมเป็น พ.ศ.) ให้เป็นคริสต์ศักราช (ค.ศ.) เพื่อให้สอดคล้องกับตาราง `dimroomsinventory`
* **Data Filtering:** ทำการกรองข้อมูลให้เหลือเฉพาะช่วงปี 2025 เพื่อให้การวิเคราะห์อยู่ในขอบเขตที่กำหนดและลดความคลาดเคลื่อนของข้อมูลที่ถูก Generate ขึ้นมา
* **Standardization:** ตรวจสอบและปรับประเภทข้อมูล (Data Type) ในแต่ละ Table ให้ถูกต้องสำหรับการคำนวณเชิงสถิติ

### **Table 1: fact_bookings**
นี่คือตารางหลักที่เก็บข้อมูลธุรกรรม (Main Transactional Table) โดยหนึ่งแถวจะแทนข้อมูลการจองหนึ่งรายการ

* **booking_id (Primary Key):** รหัสเฉพาะสำหรับระบุการจอง (เช่น RES-10023)
* **guest_id:** รหัสเฉพาะสำหรับระบุตัวตนของผู้เข้าพัก
* **booking_date:** วันที่ทำการจองห้องพัก
* **check_in_date:** วันที่กำหนดการเช็คอินเข้าพัก
* **check_out_date:** วันที่กำหนดการเช็คเอาท์ออกจากที่พัก
* **room_type:** ประเภทของห้องพักที่จอง (เชื่อมโยงไปยัง Room Type dimension)
* **rate_code_id:** รหัสอ้างอิง (Foreign Key) เชื่อมโยงไปยังข้อมูลเรทราคา (Rate Code dimension)
* **channel_id:** รหัสอ้างอิง (Foreign Key) เชื่อมโยงไปยังข้อมูลช่องทางการจอง (Booking Channel dimension)
* **segment_id:** รหัสอ้างอิง (Foreign Key) เชื่อมโยงไปยังข้อมูลกลุ่มลูกค้า (Customer Segment dimension)
* **status:** สถานะของการจอง (เช่น Confirmed, Cancelled, Checked-Out, No-Show)
* **total_room_revenue:** รายได้รวมที่ได้รับจากค่าเช่าห้องพัก (ไม่รวมภาษีและบริการเสริมอื่นๆ)
* **number_of_rooms:** จำนวนห้องพักที่จองในรายการนี้
* **adults_count:** จำนวนผู้ใหญ่ที่เข้าพัก
* **children_count:** จำนวนเด็กที่เข้าพัก
